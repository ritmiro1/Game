# Более сильная очистка исходного видео

Запрос «в 100 раз» принят как просьба попробовать более заметную техническую обработку, **не как измеримое или выполнимое обещание**. Единственный исходник — предоставленный 480×636. Никаких дополнительных достоверных деталей из другой записи нет. Новые части тела, действия, продолжение сцены и промежуточные кадры не создаются.

## Отличие от прошлого прохода

`restore_strong.py` использует окно **до пяти настоящих кадров**: текущий и до четырёх соседних. В начале и конце ролика окно короче. Это не увеличение частоты кадров. Соседние потоки движения DIS вычисляются в обе стороны один раз; поток на два кадра составляется из двух соседних с повторной проверкой возвратного совпадения, фотометрической разницы и выхода за края. Резкая смена сцены обнуляет доверие.

Затем применяются:

1. Более сильное взвешенное временное шумоподавление только по согласующимся наблюдениям.
2. Мягкая коррекция слабых границ 8-пиксельной блочной сетки.
3. Нелокальное шумоподавление NLM по яркости, с меньшей силой на выраженных границах.
4. Guided filter малого радиуса для ровных поверхностей и двусторонняя фильтрация цветовых каналов.
5. Ограниченная коррекция оценочного размытия и сдержанная резкость с защитой от ореолов.
6. Стабилизация **только добавленного обработкой остатка**, не смешивание самой движущейся сцены.
7. Ограниченная обратная проекция на сетке ×2 с реальными соседними наблюдениями.

Нейросетевой и генеративной модели нет. Баланс белого и экспозиция автоматически не исправляются. У сильного профиля итоговая яркостная разница **до увеличения** ограничена 16 уровнями 8-битного сигнала, цветовая — пятью уровнями. После причинной стабилизации предел проверяется повторно. Отдельная обратная проекция ограничена тремя яркостными уровнями относительно кубической интерполяции. Это численные пределы изменений, не гарантия достоверности каждого обработанного пикселя.

## Выбор силы без дополнительного подтверждения

Сравниваются три профиля: `moderate`, `clean`, `strong`. Фиксированные окна около кадров **48, 303, 600, 927, 1200, 1485** распределены по всему ролику. Выбор оценивает высокочастотную составляющую в относительно ровных участках, сохранение сильных границ, среднюю яркостную разницу и дополнительный клиппинг RGB.

Ограничения: медианное сохранение градиента сильных границ ≥90%, минимум по шести окнам ≥84%, максимальная средняя яркостная разница ≤3,5 уровня, увеличение доли клиппинга ≤0,5 процентного пункта и медианное уменьшение высокочастотного RMS ровных участков ≥2,5%. Среди прошедших профилей выбирается наибольшая эвристика очистки со штрафом за ослабление границ.

**Это не объективная шкала качества.** Высокочастотный сигнал включает не только артефакты, но и настоящую текстуру: сильная очистка может делать её мягче. Сохранение градиента не доказывает отсутствие всех шлейфов или ошибок optical flow. Нельзя превращать эти числа в утверждение об улучшении общего качества на какой-либо процент или в 100 раз.

Локальная проверка шести окон выбрала `strong`: медианное уменьшение указанного высокочастотного RMS около 63%, медианное сохранение градиента сильных границ около 96,8%, минимум около 96,3%. Эти числа относятся только к тесту и его определениям. Workflow заново проверяет профиль на исходнике и прекращает полный проход, если ограничения не соблюдены.

## Выходные файлы и сохранность

- Полные 1518 кадров, 30 кадров/с, исходное начальное смещение видео; таймкоды проверяются с допуском <1 мс. Исходные интервалы 2999/3000/3001 тика нормализуются, не копируются буквально.
- Полная исходная картинка, без обрезания; портретный холст 9:16 с чёрными полями.
- AAC-пакеты копируются и сверяются по SHA-256; аудио не усиливается и не перекодируется.
- Lossless-мастер FFV1 RGB 960×1272, Rice coder 0 для меньших затрат CPU.
- Экспорты непосредственно из мастера: 720×1280 H.264 Main 3.1, 1080×1920 Main 4.0, 2160×3840 High 5.1; 8 бит, BT.709, fast-start, исходный AAC.
- 4K использует `fast`, CRF 16, до 20 Мбит/с. Меньшие копии предназначены для совместимости и просмотра; 4K не загружается автоматически.
- 4K — размер выходного холста, не восстановленная нативная детализация. Все старые файлы сохраняются без изменений.

## Запуск

```bash
python -m pip install -r video-tools/requirements.txt
python -m unittest discover -s video-tools -p 'test_*.py' -v
python -u video-tools/restore_strong.py \
  --source video-tools/input/armorypass-ejoy.mp4 \
  --output-dir /path/outside/repository/restoration --profile auto
```

Отдельные стадии: `--stage prepare|render|exports|validate|notes`. `--test-frames 6` проверяет всю цепочку без оригинального звука; такие результаты помечены `test_only` и никогда не публикуются. `--preview-only` экспортирует только 720p для локального просмотра; неполный набор publisher также отклоняет.

Workflow `video-restoration.yml` запускается только на `arena/cc989019-game` отдельным `jobs/restoration-20261110.json`, не затрагивая задания старых версий. Стадии разнесены, чтобы прогресс рендера, экспорта и проверки был виден отдельно. `publish_restoration.py` проверяет состав, параметры и хеши, загружает семь вложений в отдельный draft-релиз, сравнивает все GitHub digest и размеры, затем публикует с `latest=false` и повторно проверяет постоянный публичный URL. Черновик ищется по списку и ID, не через endpoint опубликованного релиза по тегу.

Все новые крупные MP4 остаются во вложениях GitHub, а временные мастеры — вне репозитория. В Git сохраняются только небольшой код и отчёты: общий бюджет уже почти исчерпан. Локальная копия для просмотра может быть создана отдельно тем же профилем; её идентичность опубликованным байтам заявляется только после сравнения хешей.
